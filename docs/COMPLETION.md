### 任务完成动画（`src/boot/done.*`）

一轮任务**正常结束**时，在正常界面之上叠一层四拍收尾动画。它全程 `pointer-events:none`，
**点一下鼠标或按任意键就消失** —— 那一次按下不会被吞掉，它同时抵达你真正瞄准的那个元素。

| 拍 | 时长 | 表现 |
| --- | --- | --- |
| ① 反向红色 S 扫屏 | 起于 120ms，扫完约 1.36s | 与启动动画**同一条 S 路径倒过来**：zone2 R→L → zone1 R→L 反向 → zone1 L→R → zone0 R→L，即右下起、左上收。分块粒度（zone 内 5 个小块 / 15 个小块的特殊面板）与 `RED_RISE` 180ms / `RED_HOLD` 400ms / `RED_EXIT` 280ms 三个系数与启动动画逐字一致 |
| ② 矩阵像素定格 | 跟着红扫走，全屏铺满约到 1550ms | 黑幕上重画"界面的矩阵像素版"，尺寸**与启动动画收尾那套标记逐字对齐**（用户 2026-10-10："还可以再缩小一点，与启动动画里蓝扫的大小类似"）：同一个 **24px 晶格**（= 启动动画的 `CELL_SIZE 12 × UI_CROSS_STEP 2`）、符号 **8.16px**（= 晶格 × 0.34，正是启动动画的缩放值）、线宽 `max(0.9, 符号 × 0.20)`（启动动画标记的同一条公式）、圆头圆角。**每一格都要有符号**：格心落在哪块地盘就画那块的符号，边界上直接换符号、**不留空档**（"矩阵之间有明显的分界线，这些分界线也需要填充上去"）。四块地盘只换形状：**侧栏=红十字**、**输入框=红方框**、**输出文本区域=墨色方框**、**其余空白=墨色实心圆**（圆比方框轻一档：半径 = 边长 × `UI_DOT_SCALE` 0.30）。**矩阵是跟着红扫逐块亮起来的**：某一块的红一开始溶解，那一块的矩阵就在它底下淡入 |
| ③ 渐变为纯黑 | 900ms 淡出 + **700ms 纯黑静置** | 矩阵整体淡出，然后**在纯黑上停 0.7s**（"多留一点黑屏的时间"） |
| ④ 逐块硬切 → 点阵 → 绿横幅 | 0.52s + 1s + 0.5s | 满屏 80px **纯黑方块**（与「配色切换」同一尺寸、同一套 `mosaicOrder` 乱序）**逐块硬切消失** —— 没有模糊、没有半透明、没有描边（就是「黑白切换」那一套"逐块变色"的逻辑）；露出来的就是**底下的正常界面**。于是白点阵接上（`任务完成动画.html` 那片会漂移、会闪灭的点阵，去掉了原稿的 `#04060a` 底色与暗角/扫描线 —— 它要浮在界面之上，一层不透明的底会把界面盖住）；再约 1s 绿色横幅自左向右展开。此后保持不动，等一次点击 / 按键 |

**两套配色都适配**：④ 那一拍浮在**正常界面**上，点阵与角标线的墨色由 `done.css` 的
`--md-ink` 给出，并在 `body.mar-bg-light`（主白 + 绿）下翻成 `#0B0D0B` —— 否则白点阵会画在
白色界面上，等于没画。② 那一拍不吃这个变量：它底下是自铺的黑幕，两套配色下都是
"黑幕 + 红十字 / 红方框 / 墨符号"。

**触发**要回答的只有一个问题：**这一轮什么时候算结束了**。四条判据并行，谁先看到都算，
全部汇到一个 `doneEndedRound()`：

1. **DOM：`[data-turn-tail]` 又追加了一个节点**（主判据）。每轮收尾时 DSH 会在转录里挂一个
   回合尾巴节点 —— 计费纸条就是贴它上面的（见 `docs/COMPATIBILITY.md`），所以这个锚点在真机上
   是**已经在用、可验证**的。不需要会话 id，也不受快照推送批次影响。
   **但它必须区分"真的又结束了一轮"和"转录刚挂上来"**：后者会把整段历史里的尾巴一次铺出来，
   当成回合结束就变成"启动动画一结束自己播一次 / 切回旧会话又重复播"（用户 2026-10-10 报的这两个
   问题就是这一条）。所以加了两道闸：
   - **同一个转录**：上一次看到的尾巴节点**还在文档里**（说明没人把转录换掉，这就是一次追加）；
     还没有尾巴时，容器必须还是同一个且仍在文档里；
   - **先看见回合在跑**：`[class*="_turnStatus"]` 出现过一次（上升沿）之后，多出来的尾巴才算结束。
     挂载历史时从没见过 running，于是绝不触发。
   挂载 / 切换会话 / 整屏重绘只更新基线、不触发，并在 console 记一行"转录换了…不触发"。
2. **DOM：`[class*="_turnStatus"]` 从有到无**（回合进行中指示器，本主题的样式表里本来就有
   这个锚点）。
3. **会话面**（`sessions.binding(id).session`）快照里那个**单调计数器**
   `ConversationSnapshot.turnEnds`（`Map<轮次号, seq>`，每结束一轮多一项）：**它涨了就是刚
   结束一轮**，中间态有没有被看到都不影响。为什么不只看 `running` 的边沿：短任务完全可能在
   两次快照推送之间就把 `true → false` 走完（快照批量推送时更看不到），那样边沿判据会漏掉
   整轮 —— 用户 2026-10-10 怀疑"任务时间太短"正是这一条。
4. **列表快照**（`sessions.list`）里当前会话的 `running` 边沿 —— 只有宿主暴露了 `list` 时才有
   （**真机 0.2.0-rc 的客户端 `sessions` 服务面没有 `list`**，见下），另外两条 `running` 边沿
   （会话面自己的 / 列表的）同样是判据。

每个会话**第一个读到的值只作基线**（切进一个已经在跑的会话不会误报）；判定出"刚结束一轮"
后**等 350ms 再复查一次**（还在跑就让位），播放期间又开一轮则整段收掉。

**不播的三种收尾**：① 用户按了停止 —— DSH 的停止按钮调会话面上的 `cancel()`，主题就地包一层
记一笔（直取用户意图，比读收尾节点上的标记稳；**只有那一刻真的在跑才算数**，否则某些收尾路径
自己调的 `cancel` 会把正常完成一起吞掉）；② 收尾 assistant 节点带 `interrupted: true`
（"已停止"标记的来源）；③ 收尾是 `turn-error` 节点。三条任一条命中都不播，而且标记只在本轮
有效，下一轮开始即清。**拿不到会话 id 时**（见下）退一步读 DOM：刚收尾的那一轮里带
"已中断 / 已停止"字样就当用户中断，不播。

**订阅是"迟到"的，而且服务面比文档窄**：客户端服务由各插件自己 `register`，`apply()` 那一刻
`ctx.get('sessions')` 还是空的 —— 只取一次就等于永远没订阅（0.4.0 第一版真机首测的症状）。
所以这里首选 `ctx.inject(['sessions'], …)`（宿主半边挂 `webServer` 用的是同一个写法），并保留
"现取 + 每 400ms 补挂（约 30s）"这条兜底，`connection/reset` 后再补一次。

**关键事实（0.4.0 第二次真机首测的真凶）**：真机客户端 `sessions` 服务面是
`{ retain, using, retainInfo, refreshProjections, search, fork, scope, binding }`
—— **没有 `list`**（用 Cordis Inspect 向运行中的客户端核实过）。上一版 `installDone()` 要求
`sessions.list.subscribe` 是函数，否则直接放弃 → 触发链**从来没装上**，表现为"预览能播、
真任务永远不播"。现在只要服务面可用就装上，`list` 有就顺带订阅；DOM 那两条判据本来就跑，
**主判据不依赖任何会话 id**。

**怎么确认触发链是活的**：设置 ›「主题设置」里那行小字会写清当前状态 + **最近一次的判定结果**
（已播放 / 新一轮已经开跑，跳过 / 那轮是停止·中断·报错收尾 / 刚结束的那轮不在当前显示的
会话里 / …）；DevTools 里 `__marDoneDebug()` 还能看到订阅与计数器（`faceSubscribed` /
`turnSeen` / `last`）。

**调参**：`src/boot/engine-done.js` 顶部的 `CFG`（四拍时长、晶格与符号尺寸、方块尺寸、
点阵参数、默认文案）。改完必须 `node scripts/build.cjs` —— 引擎是以 JSON 字符串内嵌进
`client.js` 的。**别给 ④ 的旋钮起 `TILE_SIZE` 这种名字**：① 的迷宫 tile 边长已经叫这个，
撞名会把面板划分整个带偏（有静态守卫）。

**开发期复核（脚本不随本仓库发布，这里只记结论）**：
- jsdom 覆盖：基线静默 / 边沿触发 /
  **订阅迟到**（`ctx.inject` 回调与无 `inject` 时的补挂轮询各测一遍）/
  **短任务**（列表一次 `running=true` 都没推、只有会话面 `turnEnds` 涨了一轮 —— 必须照播）/
  每一轮各有一次（计数器按轮递增）/ 列表边沿单独也能触发（兜底路径）/
  用户按停止抑制且不泄漏到下一轮 / 中断与报错抑制 / 中途 interrupted 但收尾正常的那一轮照播 /
  新一轮让位 / 点按关闭 / 开关关掉与 `prefers-reduced-motion` 都不挂载 / 无 sessions 服务也能
  apply / dispose 退订 / **挂载历史不误播、切会话不重播**；
- 无头 Chromium + 假 DSH DOM + 像素读回（1600x952，按真机几何搭 rail 276 /
  `RlGAzG_card` 780x94 贴底 / `[data-conversation-scroll]`），逐拍断言
  —— 红扫 150ms 时只有右下那一块是红的、结束前 200ms 只有左上那一块是红的；
  **矩阵跟着红扫亮起**：红扫还在跑时（`MARK_AT + 400`）矩阵已经出现且都在
  下半屏 —— 这是"逐块跟着走"的可证伪证据；
  全屏铺满时四块地盘都在 **24px 晶格、同一相位**（十字 480 / 红方框 132 / 墨方框 1925 /
  墨点 143 = 视口格位数，一个不差）；黑幕那一拍 1523200/1523200 像素全黑；硬切方块 240 块、
  中途同一帧里既有黑块也有界面本色；绿色横幅 96448px 完全展开、点阵不穿透它、下方界面仍可读；
  切到主白 + 绿后墨色翻成 `#0B0D0B` 且暗点仍在、白点归零。
  ①②③ 与方块揭示都是时间的纯函数（方块由 JS 驱动而非 CSS 动画），复核时用引擎暴露的
  `window.__mbDone.seek()`（**测试专用** hook，按 16ms 小步重放并冻结该帧）抓帧；
  只有横幅的 CSS 展开走墙钟 —— 一次截图会晚到 300–600ms，按时间 seek 过去拍到的会是另一拍。
